DAYLOG — Complete Edition (v69)
時間の記録・日課・複合分析をひとつにまとめた、ローカル保存型の時間記録アプリです。

■ ファイル構成
- index.html：アプリ本体
- manifest.webmanifest：PWA設定
- service-worker.js：オフライン用キャッシュ
- icon.svg / icon-*.png / icon-*.svg：アプリアイコン
- logo*.svg：アプリ内ロゴ

■ 公開・インストール
1. このDAYLOGフォルダー内のファイルを、階層を保ったままHTTPS対応Webサーバーへ配置します。
2. ブラウザーで index.html を開きます。
3. PWAとして使う場合は、iPhoneではSafariの共有メニューから「ホーム画面に追加」、Androidではブラウザーのインストール操作を使います。
4. 更新時は同じ公開先へフォルダー内のファイル一式を上書き配置します。HTMLだけを置き換えず、Manifest・アイコン・Service Workerも一緒に更新してください。

■ タイマー
- ラベル／サブラベルを選択して計測し、一時停止・再開・終了ができます。
- 計測は時刻と時間区間を保存し、画面を閉じた後も次回起動時に経過を再計算します。
- 自動終了はラベルごとの既定値、またはその回だけの設定を使えます。
- タイマーカード左上の小さなSVGボタンは、タイマーと背景アニメーションをアプリ画面いっぱいに広げます。ブラウザーや端末のFullscreen APIは呼び出しません。ボタンまたはEscapeキーで通常表示へ戻れます。
- 画面いっぱいの表示中も計測は継続します。端末のセーフエリアを考慮して表示します。

■ 毎日の日課
- タイマー設定の下にある折りたたみ式チェックリストで、日課を追加・編集・削除し、当日の完了状態を記録できます。
- 日課項目は翌日以降も引き継がれ、チェック状態だけが日付別に保存されます。
- 追加・編集・削除・チェック変更は保存に成功した場合だけ確定し、保存失敗時は元の状態に戻します。
- 同名の日課の重複を防ぎ、最大60項目、1項目80文字までです。日付別チェック履歴は最新730日分を保持します。

■ カレンダーと記録
- 日別の合計記録時間・セッション数・時間帯別グラフ・ラベル内訳・セッション履歴を確認できます。
- カレンダーから日付を選択し、過去の記録を振り返れます。
- 分析期間で使う開始日・終了日は、iOSのネイティブ日付入力に依存しないアプリ内カレンダーから選択します。

■ 推移分析
- カレンダーの下の「推移を見る」を開いたときだけ集計・グラフ描画を行います。閉じている間は重い分析処理を実行しません。
- 期間は「週」「月」「3ヶ月」「記録のある全期間」「カスタム」から選べます。
- 分析対象は記録済み全体、選択したラベル／サブラベルの合算、未記録時間、記録済み／未記録の比較に対応します。
- 複数の推移を同じグラフへ最大8系列まで重ねて表示できます。各系列は凡例と個別の合計・平均・前期間との差で確認できます。
- グラフ形式は折れ線・割合表示を切り替えできます。長期間のグラフは視認性のため最大120区分に平均化しますが、期間合計などの数値は全データから計算します。
- 未記録時間は、各日の実時間から記録区間の重複を除いた合計を差し引いて算出します。睡眠や休憩などの内容を自動推測するものではありません。今日の未来時間は集計しません。

■ 設定・アニメーション
- ラベル名・色・並び順・サブラベル・自動終了の既定値、ライト／ダークテーマを設定できます。
- タイマー背景は川の流れ、枝葉の影、木漏れ日、雲の明暗変化で構成され、アニメーションのON/OFFと豊かさを調整できます。
- ボタンの操作アイコンはインラインSVGで統一しています。

■ 保存とバックアップ
- データは利用中のブラウザー／端末の localStorage に保存されます。アカウント間・端末間で自動同期はしません。
- JSONバックアップには計測記録、時間区間、ラベル・サブラベル、設定、日課、日付別チェック履歴が含まれます。
- JSON読み込み前に形式・ID・時間区間・計測状態などを検査します。不正なファイルや保存失敗時は現在のデータを置き換えません。
- 分析画面の表示条件（期間・分析対象・系列選択など）はブラウザー内に別保存され、JSONバックアップには含まれません。別端末では分析条件を再設定してください。
- 端末変更やブラウザー変更の前に「JSONを書き出す」でバックアップを作成し、新しい環境で「JSONを読み込む」を使ってください。定期的なバックアップをおすすめします。
- 保存データ形式はv6です。v5→v6の移行とv5・v6のJSONバックアップ読み込みをテスト用データで確認しています。v3・v4の過去版データは実物の保存ファイルを使った検証ができていないため、互換性を保証しません。

■ アイコンについて
- Manifestは192×192px・512×512pxのPNGとMaskableアイコンを指定し、iOS向けに180×180pxのApple Touch Iconを指定しています。
- ホーム画面アイコンはOSが追加時に取得する画像です。アプリ内のライト／ダークテーマには自動追従しません。

■ v69 データ互換性の仕上げ
- 保存キーは従来どおり daylog.data.v3、データ形式はv6です。UI変更だけを理由にデータ形式番号を上げていません。
- v5データはv6へ起動時に正規化され、日課が未登録なら空の日課一覧を補います。記録・ラベル・サブラベル・設定は同じ構造で引き継ぎます。
- v6の日課一覧と日付別チェック履歴はそのまま引き継ぎます。JSONバックアップのformatVersion 5・6を受け付けます。
- 起動時移行は、localStorageへの保存が成功した場合だけ完了扱いにします。保存に失敗した場合は旧データを上書きせず、次の保存機会に再試行します。
- v63形式（v5）からv68形式（v6）、v64・v67形式（v6）からv68形式（v6）への移行、v5・v6 JSON読み込みをテスト用データで検証しました。
- 更新時は同じHTTPSオリジン・同じ公開フォルダーへ全ファイルを上書きしてください。別ドメイン・別オリジンではlocalStorageは共有されません。更新前にJSONバックアップを作成してください。

■ v68 最終仕上げ
- タイマーの画面拡大ボタンは、見た目を小さく保ったままタップ領域を44×44pxにし、タッチ操作性を改善しました。
- Service Workerのキャッシュ削除対象をDAYLOG固有のキャッシュ名と既知の旧バージョン名に限定しました。同じドメイン上の別アプリのキャッシュを広い接頭辞で削除しません。
- READMEを現行機能に合わせて整理しました。

※ PWAのインストール・ホーム画面アイコン・iOS実機表示は、公開先のHTTPS環境と端末で最終確認してください。
