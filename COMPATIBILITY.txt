DAYLOG v145 compatibility
=========================
- Data format remains v6; localStorage key remains `daylog.data.v3`. Routine item/check structures, `routines.resetTime`, session history, analysis preferences, and JSON backup format are unchanged.
- The daily-reset time-wheel synchronization now treats normalized stored data as authoritative until the wheel is visible. This prevents a hidden wheel's zero scroll offset from being written/displayed as 00:00 during startup. When opened, the wheel is positioned to the saved value and then paints its selection.
- Default reset time remains 05:00. Existing valid saved reset times are retained. Older v5-shaped backups without `routines` continue to normalize to an empty routine list and reset time 05:00; this path was exercised with a v5 backup fixture.
- Storage failure protection remains transactional: a simulated quota exception on routine mutation left the previous serialized `daylog.data.v3` snapshot unchanged, and the previously saved routine reloaded from the saved snapshot.
- PWA Service Worker cache: `daylog-final-stability-v145`; `daylog-auto-stop-note-refined-v144` is registered as a known legacy DAYLOG cache. Cache cleanup remains restricted to known DAYLOG cache IDs / the DAYLOG cache prefix.
- Standalone HTML and PWA `index.html` are byte-identical.
- Device-specific browser persistence, iOS Safari, and a real installed-PWA session require physical-browser validation and are not certified by the automated environment.
