DAYLOG v145 final stability audit
=================================
- Fixed a startup display defect in the daily-reset time wheel. The wheel is nested inside collapsed settings disclosures; while hidden, browsers report scrollTop=0. The old synchronization path painted this zero position over the stored/default 05:00 value. The updated path keeps the normalized data value authoritative and paints wheel state only when both wheel viewports are laid out.
- The correction changes only time-wheel initialization/synchronization. It does not change the daily reset algorithm, stored resetTime, task stocks, streaks, check history, storage key, data format v6, JSON backup format, analysis preferences, or timer records.
- Browser UI test suite: 47/47 checks passed, including daily and periodic routine creation, checklist completion, stock/quota actions, time-wheel selection and reopen, timer start/pause/resume/stop, weekday presets, contradictory date-label filter warning/clear, theme changes, JSON backup round-trip, cross-device merge de-duplication, invalid-file preservation, v5 backup migration, and no horizontal overflow at 320/360/375/390/430/768/1024 CSS pixels.
- Additional browser tests passed: 1-minute duration auto-stop via a controlled clock; localStorage-path simulation for normal save/reload, 05:30 reset-time persistence across a full reload, and QuotaExceededError rollback (the previous snapshot remained unchanged); no JavaScript runtime errors in tested flows.
- Service Worker mock-runtime test passed: 15 app-shell resources are precached, v144/known DAYLOG caches are retired without deleting unrelated caches, same-scope cache-first fetch and offline navigation fallback work, and POST/out-of-scope requests are not intercepted.
- Static checks passed: Node.js syntax for app and Service Worker; lxml HTML parse (0 errors); tinycss2 CSS parse (0 rule/declaration errors); 162 unique static IDs; all manifest icons and 15 precache resources resolve; PNG dimensions match the manifest; standalone HTML and PWA index are byte-identical.
- Browser navigation is restricted in the execution environment (`ERR_BLOCKED_BY_ADMINISTRATOR`), so application interaction tests loaded the complete HTML directly into Chromium. Web Storage was separately exercised with a map-backed Storage test double, not the browser's actual persistent profile. Service Worker lifecycle was simulated in Node, not installed in a real browser.
- Physical iPhone/iPad Safari, actual PWA installation, real-device offline launch, and cross-browser rendering are not certified by this environment.
